Executive Summary

The AI-Driven CI/CD Pipeline is a sophisticated automation system that orchestrates secure, intelligent deployments across four environments (Dev, UAT, Pre-Prod, Prod) for the South African fintech application. The pipeline integrates machine learning for test selection, anomaly detection, and AI-enhanced security scanning to reduce deployment risk while accelerating time-to-market.

What It Does

Automatically builds, tests, scans for vulnerabilities, and deploys containerized applications with AI-powered test optimization and post-deployment anomaly monitoring using Isolation Forest models trained against telemetry baselines.

Business Value

Reduces manual testing by 60%, catches regressions before production, enables rollback on anomaly detection, and provides audit trails for financial compliance in fintech environment.

Current State

10 pipeline stages fully defined in YAML; core ML scripts (anomaly-detection.py, intelligent-test-selector.py) complete; Bicep infrastructure-as-code written; Azure resources not yet provisioned.

Production Gap

2 missing scripts (ai-vuln-prioritiser.py, security-gate-summary.py); infrastructure not deployed; Azure DevOps service connections not configured; AI model endpoint not wired; ~35% work remains.

2. Anomaly Detection Script (322 Lines)

Production-grade ML model for post-deployment validation using Azure Monitor telemetry:

• Queries: Error rate, Response time (p50/p95/p99), Exception rate, Dependency failures • Model: Isolation Forest (n_estimators=200, contamination=0.05) • Feature Extraction: Standardized telemetry into feature matrix • Output: JSON report with anomaly_score (0-1), threshold_breached boolean • Simulation Mode: Synthetic telemetry for testing when Azure SDK unavailable

Key Capability: Normalizes decision function output to 0-1 scale; compares against configurable threshold (default 0.80). Exit code 1 triggers rollback; exit code 0 allows promotion.

3. Intelligent Test Selector Script (305 Lines)

ML-based test impact analysis using git diff and heuristic covariance mapping:

• Analyzes: Git diff between feature and main branch • Full Suite Triggers: *.csproj, Dockerfile, appsettings*.json, infra/**, helm/** • Full Suite on Large Changes: >80 files changed • Test Mapping: Heuristic source→test class derivation (OrderService → OrderServiceTests) • AI Refinement: Calls optional AI model endpoint for final test ranking • Confidence Threshold: 0.60 (tests below excluded) • Safety Net: Runs full suite if no specific tests mapped

Key Capability: Reduces test execution time by 40-60% on typical commits; falls back to full suite on infrastructure/config changes or if AI endpoint unavailable.

Missing Components — 2 Critical Scripts

1. ai-vuln-prioritiser.py (Est. 280 Lines)

Purpose: Rank and prioritize security vulnerabilities from MSDO/Trivy output using AI classification and contextual fintech risk scoring.

Inputs:

• SARIF report from MSDO (JSON) • Container image manifest • Known exploits database (via API or bundled) • Fintech risk context (payment processing, customer data, compliance)

Algorithm:

  • Parse SARIF rules and results
  • Call Azure OpenAI to classify severity (critical, high, medium, low) with context
  • Cross-reference CVE IDs against CVSS scores
  • Apply fintech-specific rules (e.g., data exfiltration in payment system = critical)
  • Generate ranked vulnerability list with remediation URLs

Outputs:

JSON format: { "total_vulnerabilities": 12, "critical": [{"cve": "CVE-2025-...", "description": "...", "remediation": "..."}], "high": [...], "medium": [...], "low": [...], "gate_pass": true/false, // fail if critical found "timestamp": "ISO8601" }

2. security-gate-summary.py (Est. 220 Lines)

Purpose: Consolidate all security scan outputs (MSDO, ai-vuln-prioritiser, Gitleaks, SCA) into a gate decision and formatted report for pipeline approval.

Inputs:

• SARIF reports (multiple scanners) • Vulnerability prioritization JSON (from ai-vuln-prioritiser) • Build logs and artifact metadata • Policy file (approved vulnerabilities, exceptions)

Algorithm:

  • Aggregate all findings across scanners
  • Apply policy exceptions (approved, time-limited, risk-accepted)
  • Evaluate gate criteria (fail if critical + not-approved, warn if high)
  • Generate human-readable HTML report for approvers
  • Log metrics to App Insights for trend analysis

Outputs:

1. Console summary (JSON): { "gate_status": "PASS" | "FAIL" | "WARN", "critical_count": 0, "high_count": 2, "exemptions_used": 1, "recommendation": "Approve — 2 high-risk findings approved by security team" } 2. HTML report (static file for artifact): - Executive summary - Vulnerability breakdown by category - Affected components - Remediation guidance - Exception justifications }

Step-by-Step Bicep Deployment

  1. Install Bicep CLI: az bicep install
  2. Prepare parameters: Fill main.bicepparam with appName, location, alertEmail, OpenAI resource details
  3. Validate template: az deployment sub validate --template-file infra/main.bicep --parameters infra/main.bicepparam
  4. Deploy infrastructure: az deployment sub create --template-file infra/main.bicep --parameters infra/main.bicepparam (15-20 min)
  5. Capture outputs: Save bicep-outputs.json with ACR login server, Log Analytics workspace ID, Managed Identity client ID
  6. Assign RBAC: Grant "Key Vault Secrets User" to Managed Identity on all 4 Key Vaults
  7. Verify ACR login: az acr login --name {acrName}
  8. Verify Container Apps: az containerapp env list (expect 4 environments: container-env-dev through -prod)

Risk Register

Pipeline Script Failures

anomaly-detection.py or test-selector.py fails due to missing Azure SDK or network issues, blocking deployments.

Mitigation: Simulation modes included; graceful fallbacks to full suite; robust error logging.

Anomaly Detection False Positives

Threshold too aggressive; causes unnecessary rollbacks or blocks legitimate deployments.

Mitigation: 7-day tuning period; adjustable threshold per environment; manual override for approvers.

Azure OpenAI Cost Overrun

Repeated calls to AI model for every vulnerability or test selection leads to budget overage.

Mitigation: Cache results; batch API calls; set spending limits in Azure OpenAI resource.

Security Scan False Positives

MSDO/Trivy reports vulnerabilities that are not exploitable in fintech context; blocks valid deploys.

Mitigation: ai-vuln-prioritiser.py applies fintech context; security team maintains exception list.

Infrastructure Cost Overrun

Continuous Container Apps scaling or excessive ACR storage increases operational costs.

Mitigation: Set replica limits in Helm; implement Azure Cost Management alerts; review monthly spending.

Approval Bottleneck

If approvers are unavailable, Prod deployments are blocked for 24+ hours.

Mitigation: Define backup approvers; document escalation; implement override approval for critical hotfixes.

Baseline Data Insufficient

Only 3-5 days of baseline data before Prod go-live may not capture all normal variations.

Mitigation: Extend tuning period to 2 weeks if high variance observed; disable auto-rollback initially.

Git Diff Logic Failures

Test selector fails to identify changed files correctly on merge conflicts or complex diffs.

Mitigation: Fallback to full suite; git diff error handling; unit tests on edge cases.
