Executive Summary

The LNC & API Orchestration Agent is a next-generation AI-powered tool-use agent that enables engineers and operations staff to execute complex, multi-step workflows across the fintech platform's internal APIs using natural language instructions. Rather than manually chaining API calls, users describe their intent ("provision a new merchant, set up payment limits, and notify the account team") and the agent autonomously decomposes the request into an execution plan, calls the appropriate APIs in sequence, handles errors, and requests human approval at defined gate points.

The use case builds on the natural language query capabilities demonstrated in the Pulse NL Query Handler, extending from read-only queries to full read/write API orchestration with appropriate safety controls.

What It Does

Receives natural language task descriptions, decomposes them into an executable step plan using an LLM planner, executes each step against internal APIs, manages state between steps, and requests human approval before any irreversible actions.

Business Value

Reduces operator workflow time by 60–80% for multi-step onboarding and configuration tasks. Eliminates manual API call documentation. Enables non-technical staff to execute complex platform operations safely.

Risk Register

🔴 LLM Plan Hallucination — Destructive Actions

The step planner may generate a plan that includes API calls the user did not intend — particularly dangerous for write/delete operations in a financial system.

Mitigation: Mandatory plan review step before any execution; all destructive actions (DELETE, UPDATE on financial records) require explicit human approval; dry-run mode for plan validation.

🔴 Partial Execution Leaves Inconsistent State

If a 5-step orchestration fails at step 3, the system may leave the fintech platform in an inconsistent state (e.g., merchant provisioned but payment limits not set).

Mitigation: Design compensating transactions for each reversible step; define "point of no return" steps explicitly; alert on partial completion requiring manual resolution.

🔴 API Rate Limiting and Cascading Failures

Orchestrating multiple API calls in sequence risks hitting rate limits across different backend services, causing partial failures that are hard to recover from.

Mitigation: Implement exponential back-off with jitter; per-API rate limit tracking in execution engine; circuit breaker pattern; max concurrency limits per user session.

🔴 Privilege Escalation via Agent

If the agent executes API calls using a service account with elevated permissions, users could trigger privileged actions they are not individually authorised to perform.

Mitigation: Agent executes API calls using the caller's OAuth token (not a service account); tool registry enforces permission checks before adding tools to plan; CISO security review required before launch.

🟡 LLM Latency for Complex Plans

Generating a multi-step plan for complex workflows may take 5–15 seconds, which is too slow for time-sensitive operations.

Mitigation: Stream plan output as it generates; cache plans for common workflow patterns; allow users to edit generated plans before approval.

🟡 Tool Registry Maintenance Burden

As internal APIs evolve, the tool registry must be kept up to date. Stale tool schemas will cause the planner to generate incorrect API calls.

Mitigation: Auto-generate tool schemas from OpenAPI specs; add CI check that validates tool registry against live API specs; version-lock tool schemas per deployment.
