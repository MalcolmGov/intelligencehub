Executive Summary

The Pulse AIOps Root Cause Analysis engine is a real-time incident intelligence system embedded in the Pulse observability platform. It correlates multi-signal telemetry — metrics, logs, traces, and alerts — to automatically surface probable root causes during incidents, reducing MTTR by eliminating manual triage. Built on Azure OpenAI and a structured incident knowledge graph, the system produces AI-generated ops briefs and incident command views that distil noisy alert storms into actionable, prioritised summaries.

What It Does

Receives alert signals from PagerDuty/Prometheus, correlates them against deployment events and historical incidents, applies LLM-based RCA reasoning, and outputs structured AI ops briefs in the Pulse incident command view.

Business Value

Reduces average MTTR by 40–60%, eliminates alert-storm fatigue, accelerates on-call triage from minutes to seconds, and builds an institutional knowledge corpus with every resolved incident.

Current State

Core RCA pipeline (incident-rca.ts), incident command view UI (incident-command-view.tsx), alert evaluator, and AI ops brief generation are complete. Platform deployed on Vercel.

Production Gap

ML anomaly detection layer, deployment event ingestion pipeline, historical incident corpus, and ITSM/CMDB integration are outstanding. ~45% of production-grade work remains.

Risk Register

🔴 LLM Hallucination in RCA

The LLM may generate plausible-sounding but incorrect root causes, especially for novel failure patterns not well-represented in training data.

Mitigation: Implement confidence scoring, source citation in RCA output, human-in-the-loop validation for P1 incidents, and automated RCA accuracy tracking over time.

🔴 Signal Noise & Alert Storm

During major incidents, hundreds of correlated alerts fire simultaneously. Without robust deduplication and correlation grouping, the RCA engine may be overwhelmed or produce fragmented results.

Mitigation: Implement alert storm detection with automatic grouping heuristics; rate-limit RCA calls; add circuit breaker pattern for high-volume periods.

🔴 Missing Deployment Context

Until the deployment event ingestion gap is closed, the RCA engine cannot correlate incidents with code changes — the #1 root cause in most systems.

Mitigation: Prioritise deployment event ingestion as sprint 1 gap closure. Interim: manual deployment annotation via Pulse UI.

🟡 Azure OpenAI Latency

RCA during active incidents must be near-instant. If Azure OpenAI latency spikes (e.g., during high-demand periods), the ops brief delay may frustrate on-call engineers.

Mitigation: Implement async RCA with streaming output; show partial results as they generate; add fallback to pre-computed RCA templates for common failure patterns.

🟡 Cold Start — No Corpus

The historical incident corpus starts empty. Early RCA quality will be lower until enough incidents have been resolved and embedded.

Mitigation: Seed corpus with sanitised incidents from PagerDuty history on day 1; define quality threshold before enabling corpus-based RCA in production.

🟢 ITSM Integration Complexity

ServiceNow API integration may require enterprise authentication setup and CMDB data quality validation — potentially a 2-week project dependency.

Mitigation: Scope ITSM integration as Phase 2; launch production with manual ticket creation; automate in follow-on sprint.

Definition of Done — Production Readiness

The following criteria must all be met before this use case is considered production-ready:

  • ✓ Already Met: RCA engine, incident command view, alert evaluator, and AI ops brief are deployed and functional on observability-one.vercel.app
  • Gap 1: Deployment event webhook ingestion live and tested — incident-to-deploy correlation working end-to-end
  • Gap 2: ML anomaly detection model trained on 30+ days of metric baselines; false positive rate < 5%
  • Gap 3: Historical incident corpus seeded with ≥ 50 past incidents; vector similarity search returning relevant matches
  • Gap 4: ITSM integration creating ServiceNow tickets automatically for P1/P2 incidents
  • Quality: Integration test suite covering all major signal paths; RCA accuracy validated on held-out incident set > 80%
  • Ops: On-call runbook published; alert thresholds tuned; escalation path documented
  • Sign-off: Head of Engineering and CISO sign-off; 2-week shadow-mode run alongside existing manual triage process
