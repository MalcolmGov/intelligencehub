✅ What's Been Delivered

The MTN Agent Studio is built on top of the Swifter AI Platform — a production-grade agentic infrastructure codebase with significant engineering depth already in place.

Orchestration Engine

DAG-based multi-agent workflow engine with conditional routing, parallel fan-out, cycle detection, retry policies, and configurable timeout per node. Handles complex dependency trees across agent chains.

Agent Runtime

Abstract BaseAgent class, typed AgentConfig/AgentContext interfaces, AgentRegistry (type-to-constructor map), AgentExecutor with timeout racing and structured result capture. Tool framework with per-agent authorization.

API Layer

Next.js Route Handlers for agent CRUD, workflow management, analytics, and audit logs. JWT authentication middleware, RBAC middleware, rate limiting. Multi-tenant data isolation via tenantId scoping throughout.

Dashboard UI

Next.js 15 App Router admin portal with sidebar navigation. Pages: Overview (KPIs), Agents, Workflows (DAG builder via React Flow), Integrations, Logs, Analytics, Settings. Tailwind CSS design system.

Prisma Schema

11-model PostgreSQL schema covering: Tenant, User, Agent, Workflow, WorkflowNode, Execution, ExecutionLog, Integration, ApiKey, AuditLog, BillingRecord. Row-level isolation enforced at query layer.

Stakeholder Prototype

Full interactive HTML demo prototype with 8-panel navigation: Overview dashboard, 42-template library, 7-node animated DAG workflow builder, agent table, approval gates, audit trail, divisions map, integrations hub.

Risk Register

🔴 HIGH — Shadow AI proliferation worsening while platform is in build
Every month of build time is a month where ungoverned AI usage compounds across divisions. Recommend a lightweight "hold" policy communicated to all division leads immediately, paired with a committed delivery date.
🟡 MEDIUM — Azure OpenAI quota and model availability
MTN's Azure tenancy may not have GPT-4o deployment quotas pre-approved. Procurement lead time for Azure OpenAI capacity can be 4–8 weeks. Start procurement process in parallel with Phase 0 build.
🟡 MEDIUM — CISO engagement timeline
CISO sign-off is required before the approval gate mechanism goes live. Based on UC-19 precedent, this took 6+ weeks. Engage CISO in Phase 0 with threat model, STRIDE analysis, and data flow diagrams — not at the end.
🟡 MEDIUM — Division adoption without internal champions
16 divisions must actively onboard and create agents for the platform to deliver value. Without a dedicated champion in each division, passive availability won't drive adoption. Recommend identifying "anchor" divisions (Fintech, Network, HR) and driving visible wins first.
🟢 LOW — Swifter codebase coupling
The MTN internal adaptation reuses ~60% of Swifter's codebase. Any future Swifter commercial release will require careful license and IP separation. Recommend formalising the internal fork as a separate codebase under MTN's Azure DevOps from the outset.

Business Value Case

Efficiency Gain

Reduces AI initiative delivery from 6–18 months to under 2 weeks. At 5 initiatives/division/year across 16 divisions, this is 80+ initiatives annually that would otherwise not happen — or would happen outside governance.

LLM Cost Consolidation

Centralised Azure OpenAI procurement vs 16 divisions buying separately. Estimated 65% cost reduction. At $200k/yr estimated distributed spend, saving = $130k/yr baseline — scaling proportionally with adoption.

Shadow AI Risk Elimination

Ungoverned ChatGPT/Zapier usage across divisions represents POPIA violation exposure. Quantified risk: R5M–R15M per POPIA enforcement action plus reputational damage. Governance platform reduces this to near-zero.

Platform Multiplier

Every UC in the tracker (UC-1 through UC-38) could be re-implemented as an Agent Studio workflow — eliminating future per-UC engineering overhead. The platform becomes MTN's AI delivery channel, not just a single initiative.
