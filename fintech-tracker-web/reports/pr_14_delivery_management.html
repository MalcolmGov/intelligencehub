Solution Architecture

PR-14 follows a four-tier architecture enabling modular development, testing, and deployment:

Tier 1: Intelligence (AI Core)

LLM-powered analysis agents that generate semantic insights:

  • Delivery Forecast Agent: Analyzes 90-day commit history, calculates rolling velocity, scores sprint delivery risk (0-100), predicts completion % and slip days
  • Code Review Agent: Parses PR diffs, detects security/performance/complexity/breaking-change patterns (23 patterns total), generates risk scores and recommendations
  • Doc Brain Agent: Generates TL;DRs and FAQs from strategy documents for contextual awareness
  • Provider: Anthropic Claude Sonnet 4.5 (primary) + Azure Foundry (fallback)
Tier 2: Insight (Data Processing)
  • Commit Parser: Extracts metadata from git log (author, timestamp, files changed, lines added/removed)
  • Velocity Calculator: Computes rolling 2-week averages, detects 25% drop triggers
  • Risk Scorer: Aggregates points (churn risk: 5-40pts, velocity risk: 10-30pts, author risk: 5-20pts, file risk: 10-25pts)
  • PR Diff Parser: Handles unified diff format from GitHub REST, Azure DevOps REST, local git CLI
Tier 3: Integration (API & Connectors)
  • REST API: POST /forecast, POST /review, GET /metrics endpoints
  • VCS Connectors: GitHub API (Bearer token), Azure DevOps (Basic auth + PAT), GitLab (token), local git CLI
  • Messaging: Slack/Teams webhooks for risk alerts and sprint summaries
  • Portal API: Intelligence Centre for dashboard integration and historical queries
Tier 4: Interface (User Experience)
  • Dashboard: Real-time sprint health cards, risk heatmaps, contributor analytics
  • Alerts: Slack/Teams notifications for high-risk PRs (70+), sprint slip warnings
  • Portal: Intelligence Centre web UI for historical reports and trend analysis
  • Design: Antigravity palette (slate-900 bg, slate-50 text, blue-400 accents)

Current Implementation

Component 1: delivery_forecast.py (538 lines)

Purpose: Sprint delivery forecasting and risk assessment.

Key Dataclasses:

CommitSummary(author, date, files_changed, insertions, deletions) SprintMetrics(daily_commits, unique_authors, total_churn, velocity, trend) DeliveryRisk(risk_score, level, slip_days, confidence) ForecastResult(sprint, metrics, risk, completion_pct, recommendations)

Risk Thresholds:

  • Churn Risk: <50L = 5pts, 50-200L = 15pts, 200-500L = 28pts, >500L = 40pts
  • Velocity Risk: 25% drop below rolling avg triggers flag
  • Author Risk: 5-20pts per contributor diversity factors
  • File Risk: 10-25pts per high-frequency change files

Output: JSON report with risk score (0-100), level (LOW/MEDIUM/HIGH/CRITICAL), predicted completion %, slip days estimate.

Component 2: code_review_agent.py (518 lines)

Purpose: Automated PR analysis and risk scoring.

Key Dataclasses:

ReviewFinding(pattern, file, line, severity) PRRiskScore(findings, severity_pts, size_pts, test_pts, total_score, recommendation) ReviewReport(pr_id, repo, author, risk_score, recommendation, findings, ai_summary)

Pattern Library (23 patterns):

  • Security: SQL injection, XSS, hardcoded credentials, unsafe eval, auth bypass (5 patterns)
  • Performance: N+1 queries, missing indexes, unbounded loops, large allocations, inefficient regex (5 patterns)
  • Complexity: cyclomatic complexity >10, deeply nested blocks, long methods (3 patterns)
  • Breaking Changes: API signature changes, schema migrations, dependency upgrades (5 patterns)

Risk Calculation: Severity weights (critical=35pts, high=20pts, medium=10pts, low=5pts) + size penalties (>500L=+20pts, >200L=+10pts) + missing tests=+15pts.

Recommendation Logic: 70+ BLOCK, 45-70 REVIEW, 20-45 REVIEW, <20 APPROVE.

Component 3: generate_doc_brain.py (238 lines)

Purpose: Generate TL;DRs and FAQs from strategy documents using LLM.

Key Functions: flatten_content(), call_anthropic(), call_foundry(), pick_caller(), extract_json(), build_entry().

Output: doc_brain.json with 3-sentence TL;DR (<60 words), 10-15 FAQs per doc (2-4 sentence answers), category metadata, incremental mode support.

Component 4: Intelligence Centre Portal (index.html)

Purpose: Web dashboard for real-time delivery metrics.

Features: 24-item use-case library, sprint health cards, risk scores, contributor analytics, hotspot files, search/filter.

Design: Antigravity palette (slate-900 bg, slate-50 text, blue-400 accents).

Production Requirements

Infrastructure
  • Deployment: Azure Container Instances or App Service with auto-scaling (2-10 instances)
  • Database: Azure SQL Database or Cosmos DB for metrics persistence (SLA: 99.95%)
  • Cache: Redis for forecast caching and rate-limit buckets (TTL: 4 hours)
  • Storage: Azure Blob for historical reports and logs (retention: 90 days)
  • Networking: Private endpoints, VPN/ExpressRoute for secure VCS access
Security
  • API Keys: Rotate quarterly, store in Azure Key Vault, encrypt at rest
  • VCS Tokens: Use service accounts with least-privilege scope, audit log all accesses
  • LLM Prompts: Sanitize user inputs, mask PII in diffs before sending to Claude/Foundry
  • RBAC: Enforce role-based access to sensitive data (owner=READ+WRITE, team lead=READ, engineer=READ on own PRs)
  • TLS: Enforce 1.3+ for all external communications
Performance
  • Forecast latency: <5 sec (p99) with 30-min caching
  • Code review latency: <15 sec (p99) including LLM inference
  • Webhook processing: <2 sec (p99) for Slack/Teams delivery
  • Dashboard load: <2 sec (p99) for historical queries
  • LLM rate limits: Batch forecasts off-peak, implement exponential backoff for 429s
Observability
  • Metrics: Prometheus on request latency, LLM token usage, VCS API calls, forecast accuracy drift
  • Logging: Structured JSON logs with request ID, trace ID, error codes to Azure App Insights
  • Alerting: PagerDuty for forecast accuracy <75%, LLM latency >30 sec, API error rate >1%
  • Tracing: Distributed tracing across VCS → data processing → LLM → notification pipeline
  • Dashboards: Grafana with forecast accuracy trend, API health, cost tracking, adoption metrics
Runbooks
  • LLM Outage: Fall back to Foundry, then cached forecasts, then baseline heuristics. Alert owner.
  • VCS API Rate Limit: Queue requests, implement exponential backoff, alert on sustained >500/min.
  • Database Failover: Automatic replica promotion, restore from 15-min backups, 30-sec RTO.
  • False Positives: Log pattern, add to exclusion list after 3 confirmed false positives, retrain model weekly.
  • Token Rotation: Quarterly rotation with 7-day overlap period, automated via CI/CD.

Risk Register

Risk 1: LLM Latency Degradation

Impact: Forecast & review analysis delayed >30 sec, blocks PR workflow.

Probability: Medium (Anthropic API outages: ~1-2/year)

Mitigation: Implement Azure Foundry fallback with 2-sec failover, cache forecasts for 4 hours, batch requests off-peak.

Owner: Platform Team

Risk 2: VCS API Rate Limits

Impact: Unable to fetch PR diffs during high-activity periods (>500 PRs/day).

Probability: Medium (daily limits: GitHub 5000/hr, Azure DevOps 5000/sec)

Mitigation: Implement exponential backoff, queue requests, monitor rate limit headers, contact VCS providers for higher limits.

Owner: Platform Team

Risk 3: Forecast Accuracy Drift

Impact: Predictions <75% accurate after 6 months of operational data, reduces team trust.

Probability: Medium (data distribution shifts as team matures)

Mitigation: Weekly model retraining on rolling 90-day window, weekly accuracy audits, alert if drop >5%, maintain baseline heuristics.

Owner: Herman

Risk 4: High False Positive Rate

Impact: 15%+ of PRs flagged as risky when they're safe, causes alert fatigue.

Probability: Medium (pattern tuning required per team)

Mitigation: Pilot with 2 teams first, gather feedback, adjust pattern weights, maintain exclusion list, weekly tuning.

Owner: QA Team

Risk 5: PII Exposure in Diffs

Impact: Sensitive data (API keys, tokens, PII) sent to LLM providers, compliance violation.

Probability: Low (code review practices vary)

Mitigation: Sanitize diffs before LLM processing, redact common patterns (passwords, tokens, SSNs), audit diffs weekly, alert on suspicious content.

Owner: DevOps + Security Team

Risk 6: Dependency Vulnerabilities

Impact: Third-party libraries (requests, pandas, etc.) have unpatched CVEs, service compromised.

Probability: Low (dependencies actively maintained)

Mitigation: Weekly Dependabot scans, automated patch PRs, quarterly security audits, restrict to stable versions.

Owner: Platform Team

Risk 7: Team Adoption Resistance

Impact: Teams reject tool, low usage (<30%), ROI not realized.

Probability: Low (early team feedback positive)

Mitigation: Comprehensive onboarding + video tutorials, integrate into existing workflows (Slack/Teams), recognize early adopters, quarterly feedback forums.

Owner: Herman
