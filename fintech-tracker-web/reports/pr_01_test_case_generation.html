Executive Summary

High-level overview and business value

What It Does

The AI-Based Test Case Generation system autonomously creates comprehensive test cases from business requirements. It accepts inputs in multiple formats—user stories, Business Requirement Documents (BRDs), and OpenAPI/Swagger specifications—and generates production-ready test scripts in Playwright, Cypress, Jest, or Pytest. Generated tests are automatically pushed to GitHub as draft pull requests for human review and approval before merging.

Business Value

Efficiency: Reduces test authoring time by 70–80%, enabling QA teams to focus on exploratory testing and edge cases. Consistency: Ensures test coverage aligns with documented requirements, reducing gaps. Velocity: Accelerates sprint delivery by automating repetitive test creation. Cost Reduction: Lower labor overhead for routine test automation across 4+ framework ecosystems.

Current State

The system is fully implemented and operational on SentinelQA with two core components: Test Studio (909 lines React) provides the UI for requirement input and test review; test_author.py (FastAPI agent) processes requirements and invokes GPT-4 for test generation. The system successfully generates and pushes test PRs to GitHub, with active usage across multiple development teams.

Production Readiness Assessment

Functional completeness: ✓ — All core features are implemented and tested. Monitoring & observability: ⚠ — Log aggregation and alerting gaps for high-volume scenarios. Compliance: ⚠ — Audit trails and data retention policies need formalization. Disaster recovery: ⚠ — No backup strategy for generated test artifacts. Recommendation: Deploy to production with immediate focus on observability, SLA documentation, and compliance controls.

Architecture Overview

Frontend: React/Next.js 14 form interface with rich text editor for requirement input. Users can paste story format, BRD markdown, or Swagger/OpenAPI JSON. Backend: FastAPI microservice that orchestrates requirement parsing, GPT-4 invocation, and test code generation. AI Model: OpenAI GPT-4 with system prompts tailored for each test framework (Playwright, Cypress, Jest, Pytest). Output: Generated test scripts are committed to feature branches and opened as draft GitHub PRs with auto-generated descriptions.

Data Flow

User Story / BRD / Swagger ↓ Test Studio Form Input (React) ↓ POST /api/generate-tests (FastAPI) ↓ Requirement Parsing & Validation ↓ GPT-4 API Call (streaming) ↓ Test Code Generation (JS/Python) ↓ Syntax Validation & Linting ↓ Git Commit + GitHub PR Creation ↓ Draft PR + Slack Notification

Production Requirements

Infrastructure, security, monitoring

Compute & Memory

Component CPU RAM Disk Replicas
FastAPI (test_author.py) 2–4 vCPU 4–8 GB 10 GB (temp) 3 (HA)
Frontend (Next.js) 1–2 vCPU 2 GB 5 GB 2 (LB)
PostgreSQL (logs) 4 vCPU 16 GB 100 GB 1 primary + 1 replica
Redis (cache) 1 vCPU 4 GB 5 GB 1 (sentinel backup)

Networking

  • Load balancer (Application or Network LB) fronting FastAPI/frontend
  • Internal service mesh (optional: Istio) for inter-service communication
  • Outbound firewall rules: OpenAI API (api.openai.com:443), GitHub API (api.github.com:443), Slack Webhooks
  • VPC isolation: FastAPI in private subnet with NAT gateway for external API calls
  • WAF (optional) on load balancer for XSS/SQL injection protection

Secrets Management

Environment Variables (in HashiCorp Vault / AWS Secrets Manager): - OPENAI_API_KEY (string, rotated quarterly) - GITHUB_TOKEN (PAT, org-owned, rotated quarterly) - GITHUB_WEBHOOK_SECRET (for signature validation) - SLACK_WEBHOOK_URL (unique per channel) - DATABASE_URL (PostgreSQL connection string) - REDIS_URL (Redis connection string) - JWT_SECRET (for SentinelQA auth) - SENTRY_DSN (error tracking) Rotation Policy: - Quarterly for API keys (OpenAI, GitHub) - Annual for database credentials - Immediate on suspected compromise

Security & Compliance

  • HTTPS/TLS 1.3 for all external communication
  • API authentication: JWT tokens (SentinelQA auth service)
  • Rate limiting: 100 requests/minute per user (Redis-backed)
  • SQL injection prevention: Parameterized queries (SQLAlchemy ORM)
  • CSRF tokens on form submissions (Next.js middleware)
  • Audit logging: All PR creation, test generation logged to PostgreSQL with user ID
  • Data retention: Generated test code retained for 90 days, then archived
  • POPIA compliance: No PII stored; user ID only (pseudonymized)
  • PCI-DSS: No financial data handled (not applicable)

Monitoring & Alerting

Metric Tool Alert Threshold Action
Request latency (p95) Prometheus + Grafana >30s Slack alert → investigate GPT-4 API
GPT-4 API errors Sentry >5% error rate Slack → page on-call engineer

Disaster Recovery

  • PostgreSQL automated backups (daily, 30-day retention)
  • Redis persistence (RDB snapshots, every 6 hours)
  • GitHub PR artifacts versioned in S3 (30-day lifecycle)
  • RTO target: 4 hours (define SLA)
  • RPO target: 1 hour (define SLA)
  • Disaster recovery runbook (currently absent)
  • Regular DR drills (quarterly planned)

Scaling Strategy

  • Horizontal scaling: Kubernetes deployment with HPA (target: CPU 70%, memory 80%)
  • Min replicas: 3 (FastAPI); max: 10
  • Database scaling: Read replicas (2) for analytics queries; write to primary
  • Cache scaling: Redis cluster with sentinel (3 nodes) for HA
  • Expected capacity: 500 tests/day at current load; 5,000 tests/day at scale
  • GPT-4 cost at scale: ~$50/day (5,000 tests @ $0.01/test)

Implementation Guidelines

Step-by-step deployment and configuration

Prerequisites

  • Kubernetes cluster (1.28+) with 4+ worker nodes
  • PostgreSQL 14+ database (managed or self-hosted)
  • Redis 7+ (managed or self-hosted)
  • OpenAI API account with GPT-4 access (enterprise tier recommended)
  • GitHub organization with webhook permissions
  • Slack workspace with bot permissions
  • Domain name & TLS certificate for HTTPS
  • Helm 3+ for package management

1. Clone & Setup Repository

git clone https://github.com/MalcolmGov/Automation-tool.git cd Automation-tool git checkout main # Install dependencies npm install # Frontend pip install -r backend/requirements.txt # Backend

2. Configure Environment Variables

# Create .env.prod (store in Vault, not in git) export ENVIRONMENT=production export OPENAI_API_KEY=sk-proj-xxxxx export GITHUB_TOKEN=ghp_xxxxx export GITHUB_WEBHOOK_SECRET=whsec_xxxxx export SLACK_WEBHOOK_URL=https://hooks.slack.com/services/xxxxx export DATABASE_URL=postgresql://user:pass@db.prod.internal:5432/sentinelqa export REDIS_URL=redis://redis.prod.internal:6379 export JWT_SECRET=$(openssl rand -hex 32) export SENTRY_DSN=https://xxxxx@sentry.io/xxxxx export NODE_ENV=production export PYTHON_ENV=production export LOG_LEVEL=info

3. Build Docker Images

# Backend (FastAPI) docker build -f backend/Dockerfile -t sentinelqa-test-author:1.0.0 . # Frontend (Next.js) docker build -f frontend/Dockerfile -t sentinelqa-test-studio:1.0.0 . # Push to private registry docker push gcr.io/your-project/sentinelqa-test-author:1.0.0 docker push gcr.io/your-project/sentinelqa-test-studio:1.0.0

4. Deploy to Kubernetes

# Create namespace kubectl create namespace sentinelqa # Create secrets kubectl create secret generic sentinelqa-secrets \ --from-literal=openai-api-key=$OPENAI_API_KEY \ --from-literal=github-token=$GITHUB_TOKEN \ --from-literal=slack-webhook-url=$SLACK_WEBHOOK_URL \ -n sentinelqa # Deploy using Helm helm install sentinelqa-test-gen ./helm/sentinelqa-test-generation \ --namespace sentinelqa \ --values ./helm/values.prod.yaml # Verify rollout kubectl rollout status deployment/sentinelqa-test-author -n sentinelqa kubectl rollout status deployment/sentinelqa-test-studio -n sentinelqa

5. Configure GitHub Integration

# Register GitHub App # Go to: https://github.com/settings/apps/new # Settings: # - Webhook URL: https://sentinelqa.yourorg.com/webhooks/github # - Webhook Secret: (same as GITHUB_WEBHOOK_SECRET env var) # - Permissions: contents:write, pull_requests:write, actions:read # - Install on organization repos # Test webhook curl -X POST https://sentinelqa.yourorg.com/webhooks/github \ -H "X-GitHub-Event: ping" \ -H "X-Hub-Signature-256: sha256=xxx" \ -d '{"action":"opened"}'

6. Configure Monitoring & Logging

# Deploy Prometheus scrape config cat <<EOF | kubectl apply -f - apiVersion: v1 kind: ConfigMap metadata: name: prometheus-config namespace: sentinelqa data: prometheus.yml: | global: scrape_interval: 15s scrape_configs: - job_name: 'sentinelqa-test-author' kubernetes_sd_configs: - role: pod namespaces: names: - sentinelqa relabel_configs: - source_labels: [__meta_kubernetes_pod_label_app] action: keep regex: sentinelqa-test-author EOF # Deploy Fluent Bit for log aggregation helm install fluent-bit fluent/fluent-bit \ --namespace sentinelqa \ -f ./helm/fluent-bit-values.yaml

7. Smoke Tests & Validation

# Test API endpoint curl -X POST https://sentinelqa.yourorg.com/api/generate-tests \ -H "Authorization: Bearer $(curl http://localhost:8080/auth/token)" \ -H "Content-Type: application/json" \ -d '{ "requirement_text": "User can login with email and password", "requirement_type": "STORY", "framework": "PLAYWRIGHT", "target_repo": "MyOrg/MyRepo", "target_branch": "develop" }' # Verify database connection kubectl exec -it deployment/sentinelqa-test-author -n sentinelqa \ -- python -c "from sqlalchemy import create_engine; engine = create_engine(os.getenv('DATABASE_URL')); conn = engine.connect(); print('✓ DB OK')" # Verify Redis connection kubectl exec -it deployment/sentinelqa-test-author -n sentinelqa \ -- python -c "import redis; r = redis.from_url(os.getenv('REDIS_URL')); r.ping(); print('✓ Redis OK')"
