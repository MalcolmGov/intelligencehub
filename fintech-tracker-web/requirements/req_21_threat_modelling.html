Executive Summary

The AI Threat Modelling Agent automates one of the most time-consuming and inconsistently performed security activities in software development. By ingesting architecture diagrams (C4/Mermaid), PRDs and API specifications at PR time, the agent auto-generates STRIDE, DREAD and PASTA threat models — producing a living CVSS-scored Threat Register, posting executive summaries as PR comments, and generating board-ready risk heat maps against the organisation's defined risk appetite.

Malcolm Govender identified this gap after observing that threat modelling was being performed ad-hoc, often skipped under delivery pressure, and never systematically tracked in a centralised register. The cost of late-stage security remediation — discovered in staging or post-production — is estimated to be 6–10× more expensive than catching it at design time.

Problem Statement

Threat Modelling Is Skipped Under Delivery Pressure
Security reviews and threat models are frequently deprioritised when sprint velocity is the primary metric. The average time to produce a thorough STRIDE threat model manually is 2–3 days per feature. Teams simply do not have capacity to do this consistently.
No Centralised, Living Threat Register
Threat models produced by engineers live in disconnected Confluence pages, Miro boards or Word documents. There is no queryable, CVSS-scored threat register that reflects the current state of the architecture. Audit evidence is impossible to assemble.
Inconsistent Methodology & Quality
Threat model quality varies significantly by engineer experience. Junior engineers apply STRIDE inconsistently; DREAD scoring is subjective without calibration to organisational risk appetite. There is no standardisation mechanism.
Late Discovery = High Remediation Cost
Security vulnerabilities identified in production cost 6–10× more to remediate than those caught at design time. Without PR-time threat modelling, the organisation continuously absorbs this cost penalty.

Solution Overview

The AI Threat Modelling Agent operates as a PR-time security analysis service. On every pull request, it ingests available architecture artefacts and generates structured threat models using three complementary methodologies. Findings are scored, registered and communicated to developers, security engineers and executives through appropriate channels.

Threat Modelling Methodologies

STRIDE
Spoofing, Tampering, Repudiation, Info Disclosure, DoS, Elevation
Microsoft's structured threat enumeration framework applied per component and trust boundary
DREAD
Damage, Reproducibility, Exploitability, Affected Users, Discoverability
Risk scoring model calibrated to organisational risk appetite for consistent severity ranking
PASTA
Process for Attack Simulation and Threat Analysis
Business-objective-centric model for high-risk features and new system boundaries

Core Capabilities

PR-Time Threat Model Generation
Ingests C4/Mermaid diagrams, PRDs and OpenAPI specs attached to or referenced in a PR. Generates structured threat model within 10 minutes. Posts executive summary and critical threats as a PR comment in GitHub or Azure DevOps.
Living CVSS-Scored Threat Register
All identified threats are written to a centralised threat register with CVSS v3.1 base score, DREAD score, threat category, affected component, status and linked PR/Jira ticket. Register updates automatically with each PR scan.
Executive Risk Heat Map
Board-ready risk heat maps generated on demand or on schedule — mapping threat density and severity against the organisation's risk appetite matrix. Exportable to PDF for risk committee and CISO reporting.
Jira / Linear Backlog Integration
Critical and High threats automatically create backlog items in the configured issue tracker. Tickets pre-populated with threat description, CVSS score, STRIDE category, affected service and prioritised remediation guidance.

Technical Architecture

Artefact Ingestion Layer (Python)
Parses C4/Mermaid diagrams to extract components, data flows and trust boundaries. Processes OpenAPI specs to identify external-facing endpoints, authentication mechanisms and sensitive data fields. Extracts security-relevant context from PRDs using LLM summarisation.
Threat Analysis Engine (Python + Azure OpenAI)
Orchestrates STRIDE, DREAD and PASTA analysis pipelines using GPT-4o structured output. Applies organisation-specific threat library as few-shot context. Produces structured JSON threat list consumable by all downstream components.
CVSS Scoring Module (Python)
Implements CVSS v3.1 calculator with LLM-assisted metric selection validated against a human-reviewed calibration set. DREAD weights configurable per organisation risk appetite. Score reasoning exposed for audit transparency.
Threat Register Service (Python + PostgreSQL)
Persistent store for all threats with full lifecycle tracking. Exposes REST API for dashboard, digest generation and Jira/Linear integration. Implements de-duplication using semantic similarity on threat descriptions.
Integration Layer — GitHub / Azure DevOps / Jira / Linear
Webhook-based integration for PR comment posting. OAuth-authenticated connections to issue trackers. Configurable routing rules per repository and severity threshold.

Next Steps

  1. Standardise architecture diagram ingestion format across all teams — mandate C4 or Mermaid in PRD template
  2. Define CVSS scoring thresholds vs organisational risk appetite — document Critical (≥9.0), High (≥7.0), Medium (≥4.0) response SLAs
  3. Configure Jira/Linear backlog integration with routing rules per severity and repository
  4. Run pilot on one high-risk service boundary (e.g., Payment Gateway or Identity Service)
  5. Calibrate DREAD weights with CISO and security engineering team against pilot output
  6. Onboard all repositories to PR-time threat modelling in advisory mode
  7. Enable blocking mode for Critical threats (≥9.0 CVSS) after 30-day advisory period
