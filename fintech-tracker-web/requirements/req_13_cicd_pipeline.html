Problem Statement

The SentinelQA fintech platform currently relies on manual or rule-based CI/CD processes that struggle to keep pace with rapid feature deployment while maintaining security and quality standards. Key pain points include:

Current Gaps
  • Test Explosion: Test suites run in full for every commit, consuming 2–3 hours per build and blocking releases unnecessarily.
  • Security Blind Spots: Vulnerability findings lack prioritization; low-risk findings consume as much review effort as critical exploits.
  • Post-Deployment Gaps: Anomalies in production metrics go undetected for hours, delaying incident response.
  • Manual Review Burden: Security gate summaries are text-heavy PDFs; developers skip detailed security analysis before merge.
  • Resource Waste: Infrastructure provisioning is error-prone; inconsistency across staging/production environments.

This use case automates and intelligently orchestrates a 10-stage CI/CD pipeline, embedding AI/ML models at critical checkpoints to reduce build times by 60%, prioritize security findings by real exploitability, and detect deployment health anomalies within minutes. This accelerates time-to-market while strengthening security posture for a regulated fintech product.

Functional Requirements

FR-01: Trigger & Validation
Pipeline automatically triggers on push to main/develop branches and on pull requests. Branch policies enforce PR reviews and prevent force-push.
FR-02: Intelligent Test Selection
intelligent-test-selector.py analyzes code changes (diff) and selects only tests that exercise modified code paths, reducing test suite execution time by 60%.
FR-03: Multi-Stage Docker Build
Dockerfile implements multi-stage build; final image includes only runtime dependencies. Images are tagged with commit hash and pushed to Azure Container Registry.
FR-04: SAST Scanning
Semgrep scans source code for security issues (injection, auth bypass, hardcoded secrets). Findings are exported in SARIF format for integration with security gate.
FR-05: Dependency Audit
Safety (Python) and npm audit scan dependencies for known CVEs. Pipeline blocks build if critical vulnerabilities are found without explicit waiver.
FR-06: Container Scanning
Trivy scans Docker images for OS-level CVEs. Images with critical vulns are rejected; high-severity findings require security team review before push to ACR.
FR-07: IaC Scanning
Checkov validates Bicep templates for security misconfigurations (overly permissive NSGs, missing HTTPS, exposed secrets). Violations are logged and reviewed.
FR-08: Vulnerability Prioritisation
ai-vuln-prioritiser.py ranks SAST, dependency, and container scan findings by exploitability score and business impact; output drives manual review priority.
FR-09: Quality Gate Enforcement
Test execution + coverage threshold enforcement (min 85% branch coverage). Results integrated with SentinelQA test reporting; gate failure blocks merge.
FR-10: Performance Validation
k6 load test runs against staging environment; anomaly-detection.py compares metrics (response time, error rate, throughput) against baseline; deviations trigger alert.
FR-11: Staging Deployment
Bicep-driven deployment to AKS staging namespace via helm charts. Deployment waits for rolling update completion and health check success before advancing.
FR-12: Intelligent Smoke Tests
intelligent-test-selector.py curates smoke test suite for changed components post-deploy. Automated validation of critical user workflows in <5 minutes.
FR-13: Anomaly Detection (Post-Deploy)
anomaly-detection.py monitors production metrics (CPU, memory, error rate, latency) for 30 minutes post-deployment. Deviations >2σ from baseline trigger rollback + alert.
FR-14: Blue-Green Deployment
New version deployed to green slots; traffic shifted only after health checks pass. Rollback reverses traffic to blue within 2 minutes if anomalies detected.
FR-15: Security Gate Summary
security-gate-summary.py generates human-readable PR comment summarizing SAST, dependency, container, and IaC scan findings with prioritized action items.
FR-16: Artifact Management
Build artifacts (Docker images, Bicep deployments, test reports) retained for 30 days; older artifacts auto-purged to manage ACR storage costs.
FR-17: Service Connections & Environments
Azure DevOps service connections configured for AKS, ACR, Key Vault; variable groups store environment-specific configs (endpoints, secrets). Secrets injected at runtime.
FR-18: Deployment Audit Trail
All deployments logged with who, what, when, where; rollbacks recorded. Audit logs retained 2+ years for compliance (SOC 2, PCI-DSS).

Acceptance Criteria

Critical Stories (US-01, US-02, US-06)

US-01: Intelligent Test Selection
  • Test selection reduces execution time to <15 minutes for typical 3-file change
  • Coverage impact <1% (no critical paths skipped); audit confirms 2+ scenarios per covered function
  • ML model accuracy >90% (true positive rate: tests affected by change are selected)
  • Heuristic fallback activates if model confidence <80%
US-02: AI Vulnerability Prioritisation
  • ai-vuln-prioritiser.py outputs CSV: vulnerability ID, exploitability score (0–10), business impact (critical/high/medium/low), remediation effort
  • Security team validates ranking: top 5 issues manually triaged to confirm high exploitability items are ranked >7
  • False positive rate <10% (developers confirm prioritised items warrant investigation)
  • Accepts SARIF input from Semgrep, Trivy, and Safety; outputs human-readable PR comment
US-06: Post-Deployment Anomaly Detection
  • anomaly-detection.py monitors 30 minutes post-deploy; metrics include latency (p95), error rate, CPU, memory
  • Alert triggered if metric deviates >2σ from 7-day baseline; false positive rate <5%
  • Automatic rollback executes within 2 minutes of anomaly; health check passes before declaring success
  • Baseline collected for 2+ weeks before anomaly alerts enabled; confidence interval grows as data accumulates

Pipeline Architecture Overview

The 10-stage CI/CD pipeline orchestrates code from commit to production monitoring:

1 Trigger & Validation
Branch policy enforcement, PR validation, commit lint checks. Blocks merge if policies violated.
2 AI-Powered Test Selection
intelligent-test-selector.py analyzes code diff; ML model selects affected tests. Reduces suite from full 2h to 15–30 min.
3 Build & Containerise
Multi-stage Docker build, layer caching, image tagged with commit hash. Pushed to Azure Container Registry.
4 Security Scanning
Parallel: Semgrep (SAST), Safety/npm audit (dependencies), Trivy (container), Checkov (IaC). All findings exported to SARIF.
5 AI Vulnerability Prioritisation
ai-vuln-prioritiser.py ranks findings by exploitability + business impact. Critical findings require security waiver; low-risk auto-approved.
6 Quality Gate
Test execution (intelligent suite), coverage threshold (>85%), SentinelQA integration. Gate failure blocks merge.
7 Performance Validation
k6 load test on staging (45 min), anomaly-detection.py baseline check. >2σ deviation triggers alert; high deviation blocks prod deploy.
8 Staging Deployment
Bicep-driven AKS deployment to staging namespace via Helm. Rolling update waits for health checks; rollback on failure.
9 AI-Powered Smoke Tests
intelligent-test-selector.py curates smoke suite post-deploy. Validates critical workflows in <5 minutes; failure triggers staging rollback.
10 Production Deployment & Monitoring
Blue-green deploy to production AKS. anomaly-detection.py monitors 30 min post-deploy; >2σ deviation auto-rollback to blue within 2 min.

Key Inputs: Git commit (code + Bicep), test inventory, historical performance baseline (7-day window), ML test-selector model
Key Outputs: ACR image (tagged), SARIF scan reports, test results + coverage metrics, deployment logs, anomaly alerts, production version release notes
