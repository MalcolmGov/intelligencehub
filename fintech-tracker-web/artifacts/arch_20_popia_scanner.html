Section 01
Project Overview

AI-powered POPIA compliance scanner embedded in the SDLC pipeline.

Mission: Detect PII exposure, missing consent flows and unlawful data retention across APIs, DB schemas and microservices — auto-generating POPIA gap reports, remediation tickets and a living data-flow map aligned to Information Regulator requirements, FSCA guidance and SARB supervisory expectations.
🏗
Primary Stack

Python (scanner engine, NLP, PII detection) & TypeScript (CI/CD integration, API gateway, report renderer). 11 source files spanning scanner, analyser, mapper and reporting modules.

📋
Regulatory Scope

POPIA (sections 8–25), GDPR-adjacent controls, FSCA Conduct Standard requirements, SARB supervisory technology expectations and Information Regulator notification obligations.

Section 03
Component Overview

Six primary subsystems and their responsibilities.

🔍
Scanner Engine

Core orchestrator written in Python. Accepts repository URL or file path, coordinates sub-analysers, aggregates findings and produces a structured findings manifest (JSON schema). Entry point: scanner/engine.py.

🕵️
PII Detector

spaCy NER pipeline extended with South African identity patterns (SA ID number, passport, bank account, MSISDN). Scans API payloads, DB schema DDL, log configurations and environment variable references. Confidence scored 0–1.

✅
Consent Flow Analyser

Parses AST of controllers and route handlers to detect data collection endpoints lacking explicit consent capture, purpose limitation declarations or lawful basis annotations. Reports missing consent mechanisms as POPIA section 11 violations.

🗺
Data Flow Mapper

Builds a living, auto-updated Data Flow Diagram (DFD) by tracing PII from collection through processing, storage and third-party transfer. Output: interactive SVG + JSON adjacency list. Aligned to Information Regulator DFD format requirements.

📄
Report Generator

Produces POPIA gap reports in HTML, PDF and JSON. Each report includes: finding severity, POPIA section reference, responsible party, remediation guidance and estimated effort. Templated in TypeScript with Jinja2 hybrid rendering.

🔗
CI/CD Integration Layer

TypeScript GitHub Actions action and Azure DevOps extension. Exposes scanner as a pipeline step with configurable thresholds (block-on-critical, warn-on-high). Publishes SARIF format findings to GitHub Security tab and Azure Boards.

Section 06
Integration Points

External system integrations required for full pipeline operation.

⚙️
GitHub Actions

Published as a marketplace Action (malcolm/popia-scanner@v1). Triggers on PR open/push. Annotates PR with inline findings. Posts SARIF to GitHub Advanced Security.

⚙️
Azure DevOps

VSIX extension installed via Azure DevOps Marketplace. Pipeline YAML task: - task: POPIAScan@1. Publishes findings to Azure Boards work items and Security Insights tab.

🎫
Jira

OAuth 2.0 app integration. Auto-creates issues with: POPIA section reference, severity, assignee (from CODEOWNERS), remediation steps and compliance due-date based on regulatory timelines.

🏛
Information Regulator

Notification endpoint integration for section 22 breach notifications. Structured JSON payload aligned to IR prescribed format. Includes auto-population of sections 22(1)(a)–(d) from scan findings.

📊
FSCA Reporting

Export of compliance posture data in FSCA Conduct Standard format. Quarterly automated report generation with trend analysis and gap closure tracking.

🏦
SARB Supervisory

Technology risk register export aligned to SARB Guidance Note 5 on Operational Risk. Scanner findings mapped to SARB IT risk taxonomy for supervisory reporting.

Section 08
Security Considerations

Security controls built into the scanner architecture.

🔐
Zero PII Persistence

Scanner runs in ephemeral Kubernetes Jobs. Source code is cloned into /tmp on a tmpfs volume. All temporary data destroyed on pod termination. Only findings metadata (never raw PII) is persisted to the evidence store.

🔑
Authentication & Authorisation

JWT RS256 tokens issued by corporate IdP (Azure AD / Okta). RBAC: Developer (submit scans), Compliance Officer (view reports), Admin (configuration). All tokens short-lived (15min access, 8h refresh).

🌐
Network Controls

Scanner pods run in isolated K8s namespace with NetworkPolicy denying all egress except: evidence store endpoint, Jira, IR notification endpoint. No internet egress for scan pods.

🔒
Encryption

TLS 1.3 for all API communication. AES-256-GCM for evidence store. Secrets managed via HashiCorp Vault or Azure Key Vault. Git tokens scoped to read-only with 24h TTL per scan.

📝
Audit Logging

All scan invocations, report accesses and ticket creations logged to immutable audit trail (Azure Monitor / CloudWatch). Logs retained 3 years per POPIA section 55 record-keeping obligations.

🛡
Supply Chain Security

Scanner Docker image built via signed GitHub Actions workflow. SBOM generated per build (Syft). Image signed with Cosign. Admission controller enforces signed images only in production namespace.
