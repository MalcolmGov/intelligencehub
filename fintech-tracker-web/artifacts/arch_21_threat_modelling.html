🔍 1. Executive Overview

The AI Threat Modelling Agent is an automated security analysis engine embedded directly into the SDLC. It activates on every pull request, ingesting architecture diagrams, Product Requirements Documents (PRDs), and OpenAPI / Swagger specifications to auto-generate comprehensive threat models using three industry-standard methodologies: STRIDE, DREAD, and PASTA.

The agent produces a living, CVSS-scored Threat Register that persists across releases, posts actionable security summaries as PR comments in GitHub and Azure DevOps, automatically creates and prioritises tickets in Jira and Linear, and generates executive-ready risk heat maps calibrated against the organisation's defined risk appetite. Compliance coverage spans PCI-DSS and ISO 27001.

Trigger Conditions

The agent activates on: PR opened, PR synchronize, PR ready_for_review, and manual workflow dispatch. Runs only when changed files include: *.yaml, *.json, *.md, *.drawio, *.puml, docs/**, arch/**. Configured via .threat-model.yml in repository root.

📄 4. Internal API Contracts
POST
/api/v1/analyse
Trigger full threat model analysis. Accepts artefact URLs, repo context, and PR metadata. Returns job ID for async polling. Max payload: 10MB.
GET
/api/v1/jobs/{job_id}/status
Poll analysis job status. Returns: pending | running | complete | failed with progress percentage and estimated completion time.
GET
/api/v1/jobs/{job_id}/results
Retrieve full structured threat model results. Includes all threats, CVSS scores, STRIDE categories, mitigations, and compliance mappings.
GET
/api/v1/register/{repo_id}
Retrieve the living Threat Register for a repository. Supports query params: ?severity=HIGH&status=open&since=2026-01-01.
POST
/api/v1/register/{threat_id}/update
Update threat status, mitigation notes, or owner. Used by Jira/Linear webhooks to sync ticket resolution back to the register.
GET
/api/v1/heatmap/{repo_id}
Generate and return a risk heat map. Accepts ?format=svg|pdf and ?baseline=PR_ID for trend comparison.
Sample Request / Response — POST /api/v1/analyse
// Request Body { "repo": "org/payment-service", "pr_number": 342, "artefacts": { "diagrams": ["arch/payment-flow.drawio", "docs/system-context.puml"], "prd": "docs/PRD-payment-v3.md", "api_spec": "openapi/payment-api.yaml" }, "config": { "frameworks": ["STRIDE", "DREAD", "PASTA"], "cvss_context": { "env": "production", "criticality": "HIGH" }, "publish_comment": true, "create_tickets": "jira", "fail_on_severity": "CRITICAL" } } // Response { "job_id": "tm-2026-05-abc123", "status": "pending", "eta_seconds": 45 }

⚙ 6. GitHub Actions / Azure DevOps Integration
GitHub Actions Workflow

File: .github/workflows/threat-model.yml

Triggers on pull_request events targeting main and develop. Uses THREAT_MODEL_API_KEY secret. Runs as a required status check — PRs cannot merge if CRITICAL threats remain unmitigated without a Security team override.

Azure DevOps Pipeline

File: azure-pipelines/threat-model-stage.yml

Integrates as a pipeline stage using a Service Connection for auth. Posts results to PR threads and creates Work Items in the configured project. Supports branch policies to block completion on unmitigated CRITICAL threats.

# .github/workflows/threat-model.yml (excerpt) name: AI Threat Modelling on: pull_request: branches: [main, develop] paths: ['docs/**', 'arch/**', 'openapi/**', '*.md', '*.yaml'] jobs: threat-model: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Run Threat Modelling Agent uses: org/threat-model-action@v1 with: api-key: ${{ secrets.THREAT_MODEL_API_KEY }} frameworks: STRIDE,DREAD,PASTA publish-comment: true create-tickets: jira fail-on-severity: CRITICAL risk-appetite: moderate
☁ 7. Deployment Model
GitHub Actions Runner

ubuntu-latest ephemeral runner. Docker image pulled from private ECR. Stateless execution — no persistent local state.

API Service (FastAPI)

AWS ECS Fargate task. Auto-scales 1–5 replicas. Private VPC endpoint only — not internet-facing. TLS 1.3 enforced.

Threat Register Store

AWS DynamoDB (on-demand). Encrypted at rest (AES-256). Per-repository partition key. TTL: 2 years for compliance retention.

Redis Job Queue

AWS ElastiCache Redis 7. Job queuing and result caching (TTL: 24h). In-transit encryption enabled.

Heat Map Storage

S3 private bucket. Pre-signed URLs with 1h expiry. Lifecycle: archive to Glacier after 90 days.

Secrets Management

All API keys stored in AWS Secrets Manager. Rotated every 90 days. Zero secrets in env vars or source code.
