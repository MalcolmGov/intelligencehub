●Executive Summary

The Regulatory Change Impact Radar is an AI-powered regulatory intelligence platform that continuously monitors South African and international regulatory bodies — including SARB, FSCA, the POPIA Information Regulator, PCI-SSC, and FICA — for published amendments, gazettes, and guidance notes. The system automatically classifies each regulatory change by impact severity, maps it to affected internal systems and business processes, and generates board-ready impact assessments complete with implementation timelines and cost estimates for the compliance and legal teams.

This use case addresses a critical gap in the organisation's compliance posture: regulatory changes are currently tracked manually via email alerts and spreadsheets, leading to delayed response times, inconsistent impact classification, and missed implementation deadlines. The Regulatory Change Impact Radar replaces this manual process with a fully automated, AI-driven intelligence pipeline that delivers structured outputs within minutes of a regulatory update being published.

Problem Solved

Manual monitoring of 7+ regulatory bodies across multiple jurisdictions. Inconsistent impact classification leading to under- or over-resourcing of compliance efforts. Average 2–3 week lag between regulatory publication and internal awareness.

AI Approach

LangChain-orchestrated pipeline combining web scraping, LLM-based classification, system mapping via internal API registry, and structured report generation — all triggered automatically on new regulatory content detection.

Compliance Frameworks

POPIA, FICA, PCI-DSS, SARB Prudential Standards, National Credit Act, FSCA Conduct Standards. Extensible to additional frameworks via configuration.

Key Deliverable

Board-ready impact assessment PDFs auto-generated within 30 minutes of regulatory publication, replacing a process that currently takes 3–4 weeks of analyst time per significant change.

Component 1 — Feed Aggregator

The Feed Aggregator is a Python-based service responsible for continuously polling all configured regulatory sources and normalising raw content into a standard document schema. It uses Playwright for web scraping (FSCA website, Government Gazette), native RSS parsing for structured feeds, and scheduled polling via APScheduler.

Key Responsibilities

Source polling at configurable intervals (default: 4-hourly for critical sources, 24-hourly for low-frequency sources). Content deduplication via SHA-256 hashing. PDF parsing for gazette documents (PyMuPDF). Raw content stored in PostgreSQL with full audit trail. Change detection triggering downstream pipeline.

Component 2 — Change Classifier

The Change Classifier uses a LangChain pipeline with Claude as the reasoning engine to classify each new regulatory document across multiple dimensions: impact severity (Critical / High / Medium / Low), affected compliance framework, change type (amendment / new requirement / guidance / consultation), and effective date extraction.

Classification Dimensions

Impact Severity | Compliance Framework | Change Type | Affected Jurisdiction | Effective Date | Implementation Deadline | Penalty Exposure. All classifications stored with confidence scores and supporting evidence for audit purposes.

Component 3 — Impact Analyser

The Impact Analyser takes classified regulatory changes and performs deep reasoning against the organisation's known system inventory and process catalogue. It identifies which internal systems, APIs, data stores, and business processes are materially affected by each change, and estimates implementation complexity and effort.

Component 4 — System Mapper

The System Mapper maintains an internal registry of all production systems, their compliance tags, owning teams, and data categories they process. It uses vector embeddings (pgvector) to perform semantic matching between regulatory requirements and system capabilities, surfacing non-obvious compliance dependencies.

Component 5 — Report Generator

The Report Generator produces structured, board-ready impact assessment documents in HTML and PDF format. Reports include executive summary, impact classification, affected systems table, implementation timeline, cost estimates, risk-if-non-compliant analysis, and recommended action plan with owners and due dates.

Component 6 — Board Dashboard

A Next.js TypeScript dashboard providing real-time visibility into the regulatory change pipeline, outstanding compliance actions, upcoming regulatory deadlines calendar, and historical change tracking. Role-based access for compliance officers, legal team, and executive leadership.

▶Data Flow

The complete intelligence pipeline from regulatory feed to board report follows eight discrete steps, each with defined inputs, outputs, and SLA targets.

1

Regulatory Source Polling

APScheduler triggers feed aggregator jobs per source configuration. Playwright scrapes HTML/PDF content from web sources. RSS parser ingests structured feeds. New content flagged for processing.

2

Content Normalisation & Deduplication

Raw content normalised to standard schema (title, body, source, publication date, document type). SHA-256 hash computed. Duplicates discarded. New documents stored in PostgreSQL regulatory_documents table.

3

LLM Classification

LangChain pipeline invoked with structured prompt. Claude analyses document and returns JSON classification: severity, framework, change type, affected entities, effective date, implementation deadline. Confidence scores attached. Stored in regulatory_classifications.

4

Impact Analysis

Claude performs chain-of-thought reasoning over classification + system registry. Produces impact analysis: affected systems list, per-system impact severity, estimated LOE (person-days), compliance gap assessment.

5

System Mapping via Vector Search

Regulatory requirements embedded via text-embedding-3-large. pgvector similarity search against system registry embeddings. Top-k systems retrieved and ranked by relevance score + compliance tag match.

6

Cost & Timeline Estimation

LOE estimates converted to cost using configured team rate cards. Implementation timeline generated with dependencies. Board-ready Gantt data structured for report template.

7

Report Generation

Jinja2 templates populated with all analysis outputs. HTML report rendered. PDF generated via Playwright headless Chrome. Reports stored in S3-compatible object storage. Email notifications dispatched to configured stakeholders.

8

Dashboard Update

FastAPI backend event broadcast via WebSocket to Next.js dashboard. Compliance action items created in task system. Regulatory calendar updated with upcoming deadlines. Slack notification to #compliance-alerts channel.

Messaging & Queueing

Redis Streams used as the inter-service message bus. Each pipeline stage publishes events consumed by the next stage. Dead letter queue for failed processing with configurable retry (max 3 attempts).

Secret Management

Kubernetes Secrets for database credentials and API keys. External Secrets Operator syncing from HashiCorp Vault. Rotation policy: 90 days for API keys, 30 days for DB passwords.

Observability

OpenTelemetry instrumentation across all services. Prometheus metrics exported. Grafana dashboards for pipeline throughput, classification latency, and LLM token usage. Alerting via PagerDuty for SLA breaches.

Data Retention

Raw regulatory documents: 7 years (compliance requirement). Classified changes: indefinite. Generated reports: 10 years. Pipeline processing logs: 90 days. All data encrypted at rest (AES-256).
