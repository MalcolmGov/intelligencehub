USSD AI Assistant — Integration Map

End-to-end integration architecture for the intelligent middleware layer that sits between per-country MTN OpCo USSD gateways and the Mobile Money core. Covers all 13 African markets, 8 integration touchpoints, and full error/circuit-breaker strategy.

Owner: MTN Group Fintech Platform Engineering Version: 1.0 Date: 10 May 2026 Markets: 13 African OpCos Related: UC24 · UC16
Section 01

Integration Architecture Overview

Design Pattern: Hub-and-Spoke with Intelligent Middleware. The USSD AI Assistant acts as the single integration hub, normalising heterogeneous per-OpCo gateway protocols into a uniform internal event model before dispatching to downstream systems. All sessions are stateful via Redis; downstream calls are async-where-possible to keep USSD response latency within the 2-second hard limit imposed by telecom network timeouts.
🏗️
Architectural Principles
Guiding constraints for all integrations
  • ⟶ Latency budget: ≤ 2 000 ms total USSD response time
  • ⟶ Stateless hub: all session state externalised to Redis cluster
  • ⟶ Protocol normalisation: SIGTRAN + HTTP adapters per OpCo, normalised to internal HTTP/2 JSON
  • ⟶ Async enrichment: UC24 & UC16 called asynchronously; results cached in session
  • ⟶ Graceful degradation: circuit breakers on every downstream; USSD session never hangs
  • ⟶ Per-OpCo adapters: deployed as sidecar containers; updated independently
  • ⟶ Multi-tenancy: tenant ID = OpCo MCC-MNC, injected at gateway adapter layer

Section 06

Error Handling & Circuit Breaker Strategy

Principle: USSD sessions must never hang. Every downstream integration has a defined timeout, fallback behaviour, and circuit breaker. The system degrades gracefully — a user always receives a response within 2 seconds even when multiple downstream systems are degraded.
Circuit Breaker State Machine (applies to all downstream integrations)
CLOSED
Normal operation. All requests pass through. Failure counter tracked.
OPEN
Triggered at threshold. All requests immediately return fallback. Timer running.
HALF-OPEN
Single probe request sent after cooldown. Success → CLOSED. Failure → OPEN again.
Integration Timeout Open Threshold Cooldown Fallback Behaviour Alert Severity
MoMo Core 800 ms 5 failures / 10 s 30 s Return "Service temporarily unavailable"; do not debit; session ends gracefully P1
UC24 500 ms 10 failures / 30 s 60 s Use language detection only; serve default (non-personalised) menu P2
PayGuard 250 ms 5 failures / 10 s 30 s Treat all txns as REVIEW; proceed with transaction; alert compliance team P1
Redis 10 ms 3 failures / 5 s 10 s In-process session state (single request only); no cross-hop state; very limited functionality P1
NLU Engine 300 ms 10 failures / 30 s 60 s intent=UNKNOWN; engage menu-based flow entirely P2
Lang Detect 40 ms 10 failures / 30 s 30 s Use UC24 preferred language → prior session language → OpCo default P3
