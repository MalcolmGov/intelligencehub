📝 4. Register Usage Instructions

Auto-Update: This register is regenerated on every PR analysis by the UC-21 AI agent. New threats are appended; existing threats are updated with revised CVSS scores if the underlying component changes. The last_modified timestamp is stored per row in DynamoDB.

Filtering: Use the filter buttons above the table to show/hide rows by severity (CRITICAL/HIGH/MEDIUM/LOW) and status (Open/In Progress/In Review/Closed). Click column headers to sort. Use browser search (Ctrl+F) to find specific component names or threat IDs.

Status Workflow: Open → In Progress (ticket created in Jira/Linear) → In Review (mitigation implemented, awaiting security sign-off) → Closed (verified mitigated and tested). Only the Security team (Malcolm Govender) can transition to Closed status for CRITICAL and HIGH severity threats.

SLA Commitments: CRITICAL: mitigate within 14 days. HIGH: mitigate within 30 days. MEDIUM: mitigate within 90 days. LOW: mitigate within 180 days or accept with documented risk acceptance sign-off from Head of AI & Engineering.

Compliance Reporting: This register feeds directly into the quarterly PCI-DSS compliance report and the ISO 27001 Risk Assessment document. The heat map is included in the monthly security board pack prepared by Malcolm Govender.
