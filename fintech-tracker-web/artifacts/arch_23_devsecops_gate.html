Project Overview

An AI-powered security gate embedded directly into CI/CD pipelines (GitHub Actions & Azure DevOps) that combines SAST analysis with ML-driven false-positive reduction, secret scanning, dependency vulnerability scoring, and container image analysis. Critical and high-severity CVEs are blocked at merge time, SBOMs are auto-generated, and actionable remediation guidance with severity-ranked fix suggestions is posted directly on pull requests.

1. System Architecture Components

Core Engine Components

The security gate comprises eight integrated components operating as a coordinated pipeline. Each component is independently deployable and communicates via a shared scan results schema.

🔍
SAST Engine
Static Application Security Testing using Semgrep (Python, TypeScript, YAML) and Bandit (Python-specific). Runs CWE-mapped rule sets. Outputs structured JSON findings with file, line, severity, CWE, and CVSS data. Integrated with custom fintech rule packs.
🤖
ML False-Positive Reducer
Gradient-boosted classifier trained on historical PR scan data. Scores each SAST finding with a false-positive probability. Findings with confidence > 0.85 are suppressed from blocking logic but retained in audit logs. Re-trains weekly on new labelled data.
🔑
Secret Scanner
Entropy-based and pattern-matching detection for API keys, connection strings, private keys, and service account credentials. Uses Gitleaks rule sets augmented with custom fintech patterns. Scans full diff and all tracked file types.
📊
Dependency Vulnerability Scorer
OWASP Dependency Check & Safety CLI for Python; npm audit for TypeScript. Cross-references NVD CVE database, GitHub Advisory Database, and OSV. Computes an aggregate dependency risk score per package manifest. Supports pip, poetry, npm, and yarn lockfiles.
📦
Container Image Analyser
Trivy scans Docker images for OS-level CVEs, misconfigurations, and secrets. Analyses base image provenance, USER instruction compliance, and image signing status. Supports Docker Hub, ECR, ACR, and local registry images.
📄
SBOM Generator
Syft generates SBOMs in SPDX 2.3 and CycloneDX 1.5 formats for every scanned build. SBOMs are attached as pipeline artifacts and committed to a dedicated SBOM repository. Satisfies PCI-DSS Requirement 6.3 and ISO 27001 A.14.2 controls.
💬
PR Comment Publisher
Posts structured remediation guidance directly on GitHub PRs and Azure DevOps work items. Groups findings by severity, links to CVE advisories, and provides ranked fix suggestions with effort estimates. Supports @mention routing to service owners.
🚫
Pipeline Blocker
Enforces CVSS threshold policy as final pipeline gate. Sets commit status to FAILURE for Critical/High findings that pass ML filter. Writes blocking rationale to structured JSON artefact consumed by reporting dashboards. Exemption bypass requires signed approval token.

3. CVSS Blocking Thresholds

Severity Gate Policy

The Pipeline Blocker enforces the following CVSS v3.1 thresholds. Thresholds are configurable per environment via security-gate.yaml.

Severity CVSS v3.1 Range Pipeline Action PR Status Notification Exemption Allowed
Critical ≥ 9.0 BLOCK FAILURE — merge prevented Immediate CISO alert No (hardcoded)
High 7.0 – 8.9 BLOCK FAILURE — merge prevented Security team Slack alert Yes (CISO approval)
Medium 4.0 – 6.9 WARN WARNING — merge allowed PR comment + Jira ticket Yes (Tech Lead)
Low 0.1 – 3.9 INFO INFO — merge allowed PR comment only N/A
None 0.0 APPROVE SUCCESS — clean None N/A
⚠
CVSS 9.0+ (Critical) blocks are hardcoded and cannot be exempted. Any attempt to bypass via force-push triggers an automatic CISO incident notification and audit log entry under PCI-DSS Requirement 10.7.
4. GitHub Actions Integration

Workflow YAML Configuration

The security gate runs as a required status check on protected branches. The workflow file lives at .github/workflows/security-gate.yml.

# .github/workflows/security-gate.yml
# UC23 — AI-Powered DevSecOps Security Gate
name: Security Gate

on:
  pull_request:
    branches: [ main, develop, release/* ]
  push:
    branches: [ main ]

permissions:
  contents:     read
  pull-requests: write
  security-events: write

jobs:
  security-gate:
    name: AI Security Gate
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Install Security Gate
        run: pip install -r security-gate/requirements.txt

      - name: Run SAST (Semgrep + Bandit)
        run: python security-gate/sast_engine.py --output sast-results.json
        env:
          SEMGREP_RULES: p/ci,p/python,p/fintech-custom

      - name: Secret Scanning (Gitleaks)
        uses: gitleaks/gitleaks-action@v2
        env:
          GITLEAKS_LICENSE: ${{ secrets.GITLEAKS_LICENSE }}

      - name: Dependency Vulnerability Check
        run: python security-gate/dep_scorer.py --manifest pyproject.toml

      - name: Container Image Analysis (Trivy)
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ env.IMAGE_TAG }}
          format:     json
          output:     trivy-results.json

      - name: ML False-Positive Reduction
        run: python security-gate/ml_fp_reducer.py --input sast-results.json

      - name: Generate SBOM (Syft)
        uses: anchore/sbom-action@v0
        with:
          format: spdx-json,cyclonedx-json

      - name: Post PR Comment & Enforce Gate
        run: python security-gate/gate_enforcer.py --fail-on critical,high
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          CVSS_CRITICAL_THRESHOLD: 9.0
          CVSS_HIGH_THRESHOLD:     7.0
5. Azure DevOps Pipeline Integration

Azure Pipelines YAML Configuration

The security gate is implemented as a reusable Azure Pipeline template stored in a shared repository and referenced by product pipelines via resources.repositories.

# azure-pipelines-security-gate.yml
# UC23 — AI-Powered DevSecOps Security Gate (Azure DevOps)

trigger:
  branches:
    include: [ main, develop, release/* ]

pr:
  branches:
    include: [ '*' ]

pool:
  vmImage: ubuntu-latest

variables:
  CVSS_CRITICAL_THRESHOLD: '9.0'
  CVSS_HIGH_THRESHOLD:     '7.0'
  PYTHON_VERSION:          '3.11'

stages:
  - stage: SecurityGate
    displayName: AI Security Gate
    jobs:
      - job: RunSecurityScans
        displayName: Run Security Scans
        timeoutInMinutes: 15
        steps:
          - task: UsePythonVersion@0
            inputs:
              versionSpec: $(PYTHON_VERSION)

          - script: pip install -r security-gate/requirements.txt
            displayName: Install Security Gate

          - script: python security-gate/sast_engine.py --output $(Agent.TempDirectory)/sast-results.json
            displayName: SAST Analysis (Semgrep + Bandit)

          - task: trivy@1
            displayName: Container Image Analysis
            inputs:
              image:         $(Build.Repository.Name):$(Build.BuildId)
              exitCode:      false
              reportFormat:  json

          - script: python security-gate/gate_enforcer.py --fail-on critical,high --ado-mode
            displayName:   Enforce Security Gate
            env:
              SYSTEM_ACCESSTOKEN: $(System.AccessToken)

          - task: PublishBuildArtifacts@1
            displayName: Publish SBOM & Scan Results
            inputs:
              PathtoPublish: $(Agent.TempDirectory)/security-artifacts
              ArtifactName:  security-gate-results

8. Deployment Architecture

Infrastructure & Deployment Model

The security gate is deployed as a stateless Python package executed within ephemeral pipeline runner environments. No persistent infrastructure is required for the core gate; auxiliary services use managed cloud offerings.

GitHub Actions (Cloud)
  • Runs on ubuntu-latest hosted runners
  • Security gate installed from PyPI / private package feed
  • SBOM artifacts stored in GitHub Actions artifact store
  • CVE cache stored in Actions Cache (S3-backed)
  • Secrets managed via GitHub Secrets / OIDC federation
Azure DevOps (Self-Hosted Option)
  • Self-hosted agents on AKS node pool (security-hardened)
  • Pipeline artifacts stored in Azure Artifacts feed
  • Key Vault integration for secrets & signing keys
  • ML model hosted on Azure ML managed endpoint
  • Audit logs shipped to Azure Monitor / Log Analytics
Shared Services
  • SBOM Repository — dedicated Git repo (sbom-registry)
  • NVD mirror — refreshed every 6 hours via scheduled job
  • SIEM integration — Splunk / Sentinel via syslog/HTTP
  • Notification — Slack webhook + PagerDuty for Critical
  • Dashboard — Grafana boards consuming gate metrics
ℹ
Compliance Note: All scan results, SBOM artefacts, and gate decisions are retained for 12 months minimum in immutable storage to satisfy PCI-DSS Requirement 10.5 (audit log integrity) and ISO 27001 A.12.4 (logging & monitoring). POPIA data minimisation rules are applied — no source code is persisted outside ephemeral runner environments.
