Overview & Design Philosophy

The USSD AI Assistant intercepts USSD sessions at the MTN gateway layer and routes all user input through an NLU engine instead of a static menu tree. The result is a conversational, intent-driven experience on any feature phone — no app, no data, no smartphone required.

Conversational vs. Menu-Based USSD

Core Design Tenets

Progressive Disclosure
Show only what the user needs at each step. Never front-load all options. Slot-fill missing entities one at a time.
Graceful Degradation
If NLU confidence is low, fall back to a numbered menu — never abandon the user. Always offer an escape hatch.
Zero Data Dependency
All computation server-side. The handset only receives plain text. Works on 2G, EDGE, and any GSM phone manufactured after 1997.
Security First
No PII in USSD payload beyond MSISDN. PIN never transmitted. Fraud signals checked before every financial execution.

Deployment Context — 13 MTN African Markets

South Africa (ZAR) Nigeria (NGN) Ghana (GHS) Uganda (UGX) Cameroon (XAF) Côte d'Ivoire (XOF) Senegal (XOF) Rwanda (RWF) Zambia (ZMW) Congo DRC (CDF) Benin (XOF) Guinea (GNF) Sudan (SDG)

Each market runs a localised NLU model trained on that country's dialect, currency notation, and top-3 languages. The MTN MoMo API is the execution backend. All markets share the same gateway orchestrator and Redis session layer.

Network-Level Limitations

  • Synchronous only: each turn is a complete HTTP request/response cycle. No streaming, no websockets.
  • No persistent connection: state must survive between turns in Redis, not in-memory.
  • No encryption: USSD travels over SS7. No TLS. Never transmit PIN, full card numbers, or OTPs in AI-generated text.
  • No rich media: ASCII/GSM-7 only. No images, URLs, hyperlinks, or unicode emoji.
  • Character set: GSM-7 default (128 chars). Extended GSM-7 costs 2 chars per special char. Avoid accented characters where possible; French sessions use ASCII transliterations.
  • Session ID is ephemeral: no resumption after timeout. User must redial.
  • No concurrency: one active USSD session per MSISDN at a time.

Conversation Design Principles

✂

Brevity — "Every Word Earns Its Place"

With 160 chars, eliminate filler. "What would you like to do?" becomes "What can I help?". "Please confirm the following transaction" becomes "Confirm?". Every message is reviewed against a 15-word budget for the main question.

🔢

Numbered Options for Every Confirmation

Free-text responses are accepted, but every branching point offers numbered choices. Users who cannot type a full word can always press 1 or 2. This is non-negotiable for feature phone keypads and low-literacy users.

🛡

Confirm Before Every Transaction

No financial transaction executes without an explicit confirmation step. Even if intent confidence is 0.99, the user always sees "Send R500 to John? 1=Yes 2=No" before MoMo API is called. The confirmation screen includes: recipient name, verified number, amount, currency.

🔄

Error Recovery — No Dead Ends

Every error screen offers at least one recovery path. If entity resolution fails 3 times, the system gracefully moves to a numbered menu rather than ending the session. "0 = Back to menu" is always available. "CANCEL" or "0" terminates safely with a goodbye.

🌐

Language Consistency — Lock on First Detection

Once the session language is determined (either by explicit selection or auto-detection from first input), all subsequent system messages are delivered in that language. Mid-session language switches require explicit user command "LANG" or "LUGHA".

⚠

Progressive Slot-Filling — One Ask at a Time

If an intent is detected but entities are missing, ask for one missing entity per turn. Never ask "Please provide the recipient, amount, and currency." Ask "Who are you sending to?" then "How much?" This reduces cognitive load and abandoned sessions.

🔒

Security Messaging — Constant Reinforcement

PIN entry screens display "MTN will NEVER ask for your PIN" in every market language. OTP screens show a 5-minute expiry counter. Fraud-blocked sessions include a support number and never explain why the block was triggered (prevents social engineering).

Session State Machine

Every USSD session progresses through a defined set of states stored in Redis. Error states can be reached from any point in the happy path.

State Transition Rules

  • NEW_SESSION → LANGUAGE_DETECT: Always on dial-in; Redis key created with 180s TTL
  • LANGUAGE_DETECT → CONSENT_CHECK: Language selected/auto-detected
  • CONSENT_CHECK → INTENT_CLASSIFY: Consent confirmed (first-use) or already on record
  • INTENT_CLASSIFY → ENTITY_RESOLVE: NLU confidence meets threshold
  • INTENT_CLASSIFY → NLU_FALLBACK: Confidence below threshold
  • ENTITY_RESOLVE → ENTITY_RESOLVE: Self-loop for missing slot; max 3 re-prompts then NLU_FALLBACK
  • ENTITY_RESOLVE → CONFIRM: All required entities present
  • CONFIRM → EXECUTE: User sends "1" or "yes"
  • CONFIRM → ENTITY_RESOLVE: User sends "2" or "no" — edit re-entry
  • EXECUTE → RESPOND: API returns success
  • EXECUTE → FRAUD_BLOCK: Fraud engine returns block signal
  • EXECUTE → SYSTEM_ERROR: API timeout / 5xx
  • RESPOND → SESSION_END: Final message sent; END keyword
  • Any State → TIMEOUT: 180s SS7 network inactivity

Response Formatting Rules

All AI-generated USSD responses must pass an automated formatter before dispatch. The formatter enforces character budgets, pagination, abbreviations, and message templates.

Character Budgeting Rules

  • Rule 1 — Absolute limit: No response body exceeds 156 chars (160 − 4 for CON/END prefix). The formatter hard-truncates at 156 with "..." if NLU generates overlong text.
  • Rule 2 — Paginate at 130: If content exceeds 130 chars, split into pages of max 130 chars each and append "1. More 0. Done" (16 chars) = 146 total.
  • Rule 3 — Line breaks: Use "\n" between logical blocks. Each "\n" costs 1 char. Max 10 visual lines per screen (handset display limit).
  • Rule 4 — Numbers before symbols: "R500" not "ZAR500.00". "500 XOF" not "XOF 500.00". Currency symbol must fit the market convention.
  • Rule 5 — Separator lines: Use "________________" (16 underscores) for visual separation. Costs 16 chars; use sparingly.

Multi-Language Handling

The AI assistant supports 11 languages across 13 markets. Language is detected, locked to session, and used to route to the correct per-language NLU model. All system messages are translated; the NLU layer handles code-switching.

English (EN) French (FR) Swahili (SW) isiZulu (ZU) Hausa (HA) Yoruba (YO) Igbo (IG) Luganda (LG) Kinyarwanda (RW) Dioula (DY) Arabic (AR)*

* Arabic uses UCS-2 encoding — 70-char limit per USSD page. Maximum 65 chars budget applied for safety margin.

Language Detection Pipeline

Step 1 — Explicit Selection
User selects from the numbered language menu on first turn. Fastest and most reliable. Sets session.lang immediately.
Step 2 — Auto-Detect (First Input)
If user types free text before selecting language, fastText lid.176.bin model detects language in <5ms from the first 3–5 tokens. Confidence ≥ 0.80 required to set language.
Step 3 — Market Default Fallback
If auto-detect confidence < 0.80, default to the market's primary language (e.g., FR for Côte d'Ivoire, EN for Ghana). Ask user to confirm: "Reply 1 for French, 2 for English."
Step 4 — Session Lock
Once set, session.lang persists for the session lifetime. All NLU model routing and system messages use this language. User can override with "LANG" command.

Fallback Strategy

When NLU confidence falls below the threshold, the system degrades gracefully to a traditional numbered menu — maintaining the session without error, preserving trust, and ensuring task completion.

Confidence Threshold Decision Tree

Confidence ≥ 0.92 — High
Informational intents: auto-execute and respond. Skip confirmation screen. Example: CHECK_BALANCE, ACCOUNT_LIMIT.
Confidence 0.65–0.92 — Transactional
Classify, slot-fill missing entities, show confirmation screen. User must press 1=Yes before any money moves.
Confidence 0.55–0.65 — Marginal
Classify and execute for informational intents. For transactional intents, always show confirmation + offer "is this right?" clarification.
Confidence < 0.55 — Low
NLU_FALLBACK state: show numbered menu. Phrase as "I want to help — please choose:" (not "I don't understand").
3× Slot-Fill Failures
After 3 consecutive failed entity resolution attempts, abandon slot-fill and route to numbered menu with the intent pre-selected.

Traditional USSD Flow Integration

When a user opts out (OPT_OUT intent or 3× consecutive NLU_FALLBACK), the gateway flags the MSISDN in the routing database and all subsequent *170*AI# dials are silently redirected to the standard *170# USSD tree. The AI intercept layer is bypassed. This state persists until the user explicitly re-enables AI by dialling *170*AI# and selecting "Enable AI" from the welcome screen.

Accessibility & Inclusion

MTN's 13 markets include significant populations with low literacy, first-time phone users, and challenging connectivity. Inclusion is a hard requirement, not an afterthought.

🔢

Numeric Shortcuts — Always Available

Every screen that accepts free-text also accepts numeric choices. Users who cannot type sentences navigate via 1, 2, 3, 0 keys. The keypad is the universal UI. Numbered menus are never deeper than 2 levels to prevent cognitive overload on small displays.

📖

Grade-5 Reading Level — All Languages

All system messages use short sentences, common words, active voice. "Debit" → "money taken out". "Beneficiary" → "who you're sending to". Per-language plain-language review is mandatory before each market launch. NLU-generated confirmations are reviewed by a local linguist team.

🔄

Repeat / Re-read at Any Step

Typing "?" or "REPEAT" at any CON state re-displays the current prompt. This assists users who scroll past content on small 1.8" screens or who need extra time to read. The repeat does not consume a session turn count.

⏱

Proactive Timeout Warning — 60 Seconds Before

At 120 seconds of inactivity (60s before network timeout), if the session is in CON state, the gateway sends: "Session ending soon. Reply now or dial *170*AI# again." This prevents losing progress for slow typists — a known pain point for elderly and low-literacy users.

🔴

No Dead Ends — Always One Recovery Path

Every error screen offers at minimum: retry, return to menu, or call 135. The system never reaches a state where the only option is hanging up. "0 = Cancel safely" convention is consistently applied. Even FRAUD_BLOCK provides a support number.

📞

Human Escalation — Always Reachable

At any point, typing "AGENT", "HELP", "135", or "MSAADA" (Swahili) triggers SUPPORT_ESCALATE intent, creating a callback ticket with session transcript attached. The AI always responds with the local MTN customer care number in the country's dialling format.

💰

Local Currency Format — Thousand Separators

Amounts are always confirmed in local currency format with thousand separators: "UGX 1,000" not "UGX1000". For high-denomination markets (UGX, XOF, CDF), this prevents misread errors where users may miss zeros. The format is set per-market in the localisation config.

🌐

Auto Language Detection from First Input

If a user skips language selection and types in their language, the NLU language detector identifies it within 2–3 tokens and adjusts all subsequent responses automatically. No need to navigate back to the language menu. Reduces friction for users unfamiliar with menu navigation.

📢

Voice Companion — Phase 2 (Low-Literacy Markets)

For Mali, Niger, and DRC where literacy rates below 50% are documented, a Phase 2 enhancement offers voice reading of USSD content via a parallel IVR channel triggered by pressing * during the session. Text and voice remain synchronised using the same Redis session ID. Pilot: Q3 2026.

A/B Testing Plan

Continuous experimentation is built into the system. The gateway routes a percentage of sessions to variant flows. All A/B tests use session-level randomisation (by MSISDN hash) to prevent the same user seeing different variants within a week.

Experimentation Framework

  • Randomisation unit: MSISDN hash mod 100. User always sees the same variant for the experiment duration (no flip-flopping).
  • Traffic split: Default 50/50 for new experiments. Can be adjusted to 90/10 for high-risk changes.
  • Experiment duration: Minimum 2 weeks to account for weekly usage patterns.
  • Statistical significance: p < 0.05 required before shipping a winner. Minimum 1,000 sessions per variant.
  • Primary metric: Task Completion Rate (TCR) — % sessions that reach SESSION_END with success outcome.
  • Secondary metrics: Session abandonment rate, average turns to completion, NLU_FALLBACK rate, error rate.
  • Guard rails: Auto-pause if fraud block rate increases by >2% in either variant, or if SYSTEM_ERROR rate exceeds 1%.
