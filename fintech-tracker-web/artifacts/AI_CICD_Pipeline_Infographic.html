🤖 AI Capabilities

🟢 Three AI-powered capabilities embedded across the pipeline
🛡️ AI Security Prioritisation
After SAST scanning (Bandit, Roslyn, Checkov), Azure OpenAI GPT-4 re-ranks findings by exploitability and business impact — so engineers fix the vulnerabilities that matter most, not just the noisiest ones.
🧪 Intelligent Test Selection
Analyses git diff to determine which source files changed, maps them to their corresponding test classes via heuristics and coverage history, then runs only that subset — cutting test time significantly without sacrificing confidence.
📊 Anomaly Detection & Rollback
Post-deploy, an Isolation Forest model evaluates error rate, P50/P95/P99 latency, exception count and dependency failures against a 24-hour baseline. Score > 0.7 triggers automatic rollback to the previous Container Apps revision.

STAGE 1
🔨 Build & Package
Compiles the application, runs unit tests, builds and pushes the Docker image to Azure Container Registry
dotnet build docker build ACR push code coverage
What happens
  • NuGet package restore and .NET solution compile in Release configuration
  • Unit tests run via dotnet test; code coverage report published as pipeline artifact
  • Docker image built and tagged with Build.BuildId plus branch metadata
  • Image pushed to Azure Container Registry (Premium) — geo-replicated, zone-redundant
  • Pipeline artifacts published for downstream stages
Gates & outputs
  • Stage fails if unit tests fail or coverage drops below threshold
  • Triggers on commits to main, release/*, and hotfix/* branches
  • Output: Docker image acr.azurecr.io/app:$(BuildId)
  • Output: Published build artifact with test results and coverage XML

STAGE 2
🛡️ AI Security Scan
Three parallel security jobs — SAST, container scanning, IaC validation. Blocks deployment on any CRITICAL finding.
AI PRIORITISED HARD GATE MSDO Trivy Gitleaks Checkov
3 parallel jobs
  • Job 1 – SAST: Microsoft Security DevOps extension runs Bandit, Roslyn Analysers, ESLint. Azure OpenAI GPT-4 re-ranks findings by exploitability and blast radius.
  • Job 2 – Container Scan: Trivy scans the Docker image for OS and library CVEs. Microsoft Defender for Containers provides runtime threat protection.
  • Job 3 – IaC Scan: Checkov and Template Analyzer validate Bicep infrastructure templates against CIS benchmark controls.
Secrets & gate logic
  • Gitleaks scans every commit for hardcoded secrets, API keys, and credentials
  • Any CRITICAL CVE or SAST finding fails the stage immediately — no deployment proceeds
  • HIGH findings produce warnings but do not block (configurable)
  • SARIF results published to Azure DevOps Security tab for audit trail
  • Scan runs in parallel across all three jobs to minimise pipeline duration

STAGES 3 & 4
● Deploy + Test — Dev
Helm deployment to the Dev environment followed by AI-powered test selection and integration testing
AI TEST SELECT NO APPROVAL GATE Helm dotnet test
Deployment (Stage 3)
  • Pre-flight infra validation — confirms Key Vault, ACR, and App Insights are reachable
  • Helm upgrade --atomic deploys the new image; Helm rolls back automatically if the release fails to become ready
  • Secrets injected from Azure Key Vault via User-Assigned Managed Identity — no credentials stored in the pipeline
  • Smoke tests verify the app is responding on its health endpoint
  • Deployment tagged in App Insights for post-deploy correlation
AI Test Selection (Stage 4)
  • git diff analysed to extract changed source files since last green build
  • Critical file changes (pipeline config, auth, infra) trigger the full test suite automatically
  • For targeted changes: heuristic mapping links e.g. Services/PaymentService.cs → PaymentServiceTests
  • Test history service supplements heuristics with historically-failing tests for the changed code
  • Filter expression passed to dotnet test --filter; results logged to App Insights

STAGES 5 & 6
● Deploy + Test — UAT
Manual approval gate, blue/green deployment, full test suite including user acceptance scenarios and App Insights baseline
MANUAL APPROVAL AI TEST SELECT Blue/Green Smart Detection
Deployment (Stage 5)
  • Manual approval gate — a designated approver must sign off within 7 days before UAT deployment proceeds
  • Blue/green deployment: new version deployed to green revision; traffic flipped atomically via Azure Container Apps revision weights
  • Previous blue revision kept warm for rapid rollback if issues surface during testing
  • Smoke tests and UAT health checks run against the live environment
Testing & monitoring (Stage 6)
  • AI Test Selector runs the full UAT-scoped test suite including user acceptance scenarios
  • API contract tests validate backward compatibility — no breaking changes allowed
  • App Insights Smart Detection establishes a ML behavioural baseline post-deployment
  • Dynamic threshold metric alerts notify the DevOps team of error rate or latency deviations (Sev 2)

STAGES 7 & 8
● Deploy + Monitor — Pre-Prod
Manual approval gate, canary deployment at 10% traffic, performance regression checks, and Azure Monitor anomaly alerting
MANUAL APPROVAL Canary 10%→100% Dynamic Alerts
Deployment (Stage 7)
  • Manual approval gate — sign-off required before Pre-Prod promotion
  • Canary deployment: 10% of traffic routed to new revision via Container Apps revision weights
  • Smoke tests run against the canary slice; on pass, traffic shifts to 100%
  • Production-equivalent configuration and sizing — mirrors Prod infrastructure exactly
  • Deployment event tagged in App Insights for correlation with monitoring data
Monitoring (Stage 8)
  • 3-minute warm-up wait before monitoring begins to avoid cold-start false positives
  • Azure Monitor dynamic threshold alerts for error rate (Sev 2) and P95 latency using ML-learned seasonal baselines
  • Performance regression check: P95 latency compared against Dev/UAT baselines
  • Alert emails dispatched to DevOps team Action Group on threshold breach
  • No auto-rollback in Pre-Prod — anomalies alert the team for human decision
↓
STAGES 9 & 10
● Deploy + Monitor — Production
Senior engineer approval, blue/green deployment, Isolation Forest anomaly detection, automatic rollback on score > 0.7
SENIOR APPROVAL AI ANOMALY DETECT AUTO ROLLBACK Blue/Green
Deployment (Stage 9)
  • Senior engineer manual approval gate — required before any Production deployment
  • Blue/green deployment: new version deployed alongside current; traffic flipped atomically
  • Previous blue revision kept warm for 5 minutes — instant revert if anomaly detected
  • Post-deploy smoke tests confirm critical user journeys are functional
  • Deployment telemetry sent to App Insights and Log Analytics for correlation
AI Anomaly Detection (Stage 10)
  • Queries Azure Monitor Log Analytics (KQL) for: error rate, P50/P95/P99 latency, exception count, dependency failure rate
  • Isolation Forest model (scikit-learn) trained on 24-hour pre-deploy baseline; normalised anomaly score 0–1
  • Score > 0.7 triggers automatic rollback to previous Container Apps revision via Azure CLI
  • Azure Monitor dynamic threshold alerts (Sev 1) run in parallel — belt-and-suspenders approach
  • All anomaly decisions logged with score, contributing metrics, and action taken
